# Favicons and app icons

The frontend ships six icon files plus a web app manifest, all in
`frontend/public/` (Vite copies that directory to the root of `dist/`, so every
path below resolves at the site root). They are generated by
`scripts/generate-icons.sh` — `make frontend-icons` — and committed. Rerun that
only when the mark itself changes.

## Why more than one file

A single `favicon.svg` covers browser tabs and nothing else. The platforms that
show a site as an *icon* rather than a tab each read one specific thing and
ignore everything else:

| File | Read by | Ignores the rest because |
| --- | --- | --- |
| `favicon.svg` | Chrome, Firefox, Safari 16.4+ tab strips | scalable; this is the source mark, checked in as lucide exports it |
| `apple-touch-icon.png` (180×180) | iOS/iPadOS home screen, **macOS Safari Start Page favourites**, iOS share sheet | WebKit does not accept SVG or `.ico` in these surfaces |
| `icon-192.png`, `icon-512.png` | Android / Chrome, via the manifest, `purpose: "any"` | Chrome reads icons from the manifest, not from `<link rel="icon">` |
| `icon-maskable-512.png` | Android adaptive launcher icons, `purpose: "maskable"` | the launcher crops to its own shape and needs bleed to crop into |
| `favicon.ico` (48/32/16) | `/favicon.ico` root probes, older browsers, **Safari tab strip** | predates everything else and is still fetched blind |
| `site.webmanifest` | Android install / "add to home screen" | — |

The original bug this set fixed: only `favicon.svg` existed, so the mark showed
in the macOS Safari tab bar but was blank on iOS and blank in the macOS Safari
Start Page favourites grid. Both of those read `apple-touch-icon` only.

## Design constraints baked into the generator

- **Every generated tile is a white ground with a black mark, in every colour
  scheme.** Safari composites tab icons and Start Page favourites onto its own
  light chip, so a dark tile reads as a dark square with white bleeding around
  it — see the note below. A white tile disappears into that chip, and stays
  legible on the dark tab strips (Chrome, Firefox) that composite onto nothing.
  There is deliberately no `prefers-color-scheme` handling anywhere in the set.
- **`favicon.svg` is not generated.** It is the source mark, left exactly as
  lucide exports it, `currentColor` and all — which resolves to black, which is
  what Safari's light chip wants.
- **`apple-touch-icon.png` must be opaque.** iOS composites any transparency
  onto black. It is also full-bleed with the mark at 60%: iOS applies its own
  superellipse mask, so self-rounded corners would be masked twice.
- **`icon-maskable-512.png` keeps the mark inside 52% of the tile.** Android
  may crop to any shape within a circle of 80% of the tile's diameter; a square
  inscribed in that circle is 56%, so 52% leaves a margin.
- **`icon-192/512.png` are rounded and transparent-cornered.** `purpose: "any"`
  icons are shown uncropped, so the tile has to round itself.
- **`favicon.ico` uses its own, larger, heavier drawing.** It is mostly consumed
  at 16px, where the mark at the size used elsewhere closes up into a blob. It
  is square rather than rounded: the tile is flattened opaque, so a corner
  radius would only be filled back in with the tile colour.

## Colours

`PAPER` (`#ffffff`) and `INK` (`#0a0a0a`) in the generator are the app's own
`oklch(1 0 0)` and `oklch(0.145 0 0)` neutral tokens from
`frontend/src/index.css`, resolved to sRGB.

### Don't make the tile dark

This was tried and reverted. A dark tile with a light mark looks right in
isolation, but Safari does not draw favicons or Start Page favourites directly
onto its chrome — it paints a light rounded chip and composites the icon onto
that. A dark tile therefore appears as a dark square floating inside a white
surround, in exactly the dark-mode case a dark tile was supposed to help. White
ground, black mark, everywhere.
